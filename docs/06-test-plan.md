# 06. 테스트 계획

> 이 서비스의 실패는 두 방향이다: **미탐**(사고를 못 막음 — 서비스 존재 이유 상실)과
> **오탐**(무해한 문장을 차단 — 사용자 신뢰 상실). 테스트는 항상 양쪽을 동시에 측정한다.

## 1. 테스트 자산 (골든셋 3종)

| 셋 | 내용 | 합격 기준 | 출처 |
|---|---|---|---|
| `tests/golden/must_catch.jsonl` | 반드시 잡아야 하는 입력 | 재현율 ≥ 95% (severity 5는 100%) | `incident` 테이블의 실사고 문구(최우선), 위키/뉴스 용례 |
| `tests/golden/must_pass.jsonl` | 절대 잡으면 안 되는 무해 입력 | **등급별 채점** (아래 규칙) ≥ 98% | 동음이의어 일반 용례(운지버섯, 지명, 인명), 실제 마케팅 카피, 뉴스 문장, 일상 대화 |
| `tests/golden/evasion.jsonl` | 변형 회피 입력 | 재현율 ≥ 85% (점진 상향) | variant-engineer 규칙 + qa-redteam 능동 탐색 |

각 항목 필수 필드: `text(또는 image_ref)`, `expected`(매칭 용어/없음), `why`(이 케이스가 존재하는 이유), `source`(출처 URL/incident id), `added_at`.

**must_pass 채점 규칙 (등급별 — M2 게이트가 M3 산출물에 의존하지 않도록. 등급 어휘는 03 §2 단계 4: revise_recommended/review_recommended/monitor)**:
- `ambiguity != 'unambiguous'` 항목(F8 동음이의어/F9 재전유/F18-21 인용·대항표현): **M3 문맥 분류기 도입 전까지 `revise_recommended`(구 block) 발생만 실패로 카운트** (review/monitor는 통과 — 05 리스크 표의 'review 상한 기본값'과 정합). review_recommended 통과율은 분리 측정·보고하고 M3 이후 게이트화.
- `unambiguous` 및 safe_contexts로 해소 가능한 항목: **어떤 매칭이든**(review_recommended 포함) 실패로 카운트.
- 릴리스 게이트(04 §5 게이트 2)도 동일 규칙으로 채점 (빌드 게이트와 테스트 계획의 채점 불일치 금지).

**골든셋 구조는 한국형 HateCheck 체계를 따른다** (HateCheck ACL 2021, CC BY 4.0 — 한국어판 부재가 확인된 시장 공백):
- must_pass를 기능별 슬롯으로 분류: F8(동음이의어: 운지버섯·운지법), F9(재전유), F18-19(인용/보도: "○○사가 해당 표현으로 사과했다"), F20-21(대항표현: 혐오를 비판하며 인용한 문장), F11(욕설 포함 무해문), **+자체 슬롯: 자모 경계 오정렬 오탐** (사전 키의 자모 이음새를 우연히 포함하는 무해 입력 — 예: '운지'의 ㄴ|ㅈ 이음새를 가진 '원조/안주' 류 — 03 §2 단계1 음절 경계 필터의 회귀 감시)
- 근거 지표: SOTA 모델도 대항표현에서 정확도 97.9%→42.7% 붕괴(고려대 2022) — 슬롯별 통과율을 분리 보고해야 평균에 묻히지 않음
- **2024-26 실사고 영구 회귀셋**: 롯데 '노무한 박수', 스타벅스 '탱크데이', EBS '들켰노', 르노/볼보/이터널리턴/메이플 집게손 사례 — 2018-21 학술 코퍼스로 학습한 모델이 구조적으로 놓치는 유형이므로 별도 묶음으로 영구 보존, 신규 사고 보도마다 추가

**불변 규칙**: 실사고(incident)가 새로 수집되면 그 문구는 자동으로 must_catch 후보가 된다.
오탐 신고(`/v1/feedback`)가 확정되면 그 문장은 자동으로 must_pass 후보가 된다.
→ 골든셋은 운영할수록 자란다.

## 2. 레이어별 테스트

### 2.1 단위 (매 커밋, CI)
- **정규화 속성 테스트** (hypothesis): 멱등성 `norm(norm(x))==norm(x)`, 임의 유니코드 입력에 무예외
- **오프셋 매핑 불변식** (02 §4.1 — 자모 분해는 1→N 비가역이므로 '가역성' 한 단어로 끝나지 않음): `src_offset` 단조 비감소 + 길이 == `norm_text`; 왕복 검증 `normalize(원문[m.span])[0] == 사전키[m.term]` (모든 매치 m); 제로폭 삽입·종성 경계 부분 매치 케이스 명시 포함
- 변형 규칙별 생성↔매칭 왕복 테스트 (생성한 변형은 반드시 매칭됨)
- 오토마톤 빌드 결정성 (같은 사전 → 같은 체크섬)
- API 계약 테스트 (스키마, 에러 코드)

### 2.2 사전 품질 (매 릴리스, 릴리스 게이트)
- **데이터 무결성**: active 항목의 evidence ≥ 1 (origin/definition 포함), source URL 200 응답 또는 archive 존재, 필수 필드 누락 0
- **골든셋 회귀**: 3종 전체 실행 — **직전 릴리스 대비 새로 실패하는 케이스가 1건이라도 있으면 릴리스 차단**
- diff 리포트: 추가/삭제/심각도 변경 항목 목록 → 승인자 확인

### 2.3 모델 평가 (모델 갱신 시)
- 카테고리별 P/R/F1 + 혼동행렬 (특정 카테고리 편향 감지)
- **동음이의어 전용 평가셋**: 용어별 위험/무해 대조 쌍 — 용어 단위 F1 보고 (평균에 묻히는 개별 실패 방지)
- 캘리브레이션 곡선 → LLM 폴백 호출률과 비용 추정 동시 산출
- 공개 벤치마크(KOLD/UnSmile 테스트 분할)와 자체 셋 병행 — 자체 셋이 항상 우선

### 2.4 이미지 (M4부터)
- 표식별 augmentation 검증셋: 원본 + 크롭/회전/색변형/노이즈/워터마크 합성 → pHash·CLIP 임계 ROC로 결정
- OCR 경로 통합 테스트: 텍스트 박힌 이미지 → 텍스트 골든셋과 동일 판정 나오는지
- 손모양: 일반 손동작 사진 대량(오탐 측정) vs 표식 손모양 — FP율 < 5% 전까지 experimental 유지

### 2.5 레드팀 (분기 + 주요 릴리스 전)
- 혼합 변형 공격 (자모분리+leet+띄어쓰기 동시)
- 문장 분절/줄바꿈으로 패턴 절단, 제로폭 문자 삽입
- 텍스트→이미지 우회 (문구를 이미지로 렌더링)
- 신조어 시뮬레이션: 사전에 없는 최신 용어로 미탐 측정 → out_of_lexicon 경고가 잡는 비율
- 발견된 모든 회피는 evasion.jsonl에 영구 추가

### 2.6 성능/부하 (M2, M6)
- locust: 텍스트 동기 p95 < 150ms(문맥분류 제외)/500ms(포함), 처리량 목표 100 RPS — **입력 조건(≤500자, ≤10매치)을 시나리오 파라미터로 고정**
- **워스트케이스 시나리오 분리**: (a) 다중 매치 긴 마케팅 카피(Kiwi+퍼지 비용 누적), (b) batch 묶음 — 각각 별도 p95 목표로 측정해 최악 케이스가 평균에 묻히지 않게
- 사전 핫리로드 중 무중단 검증 (스왑 중 요청 드롭 0)
- 이미지 큐 적체 시나리오 (워커 다운 → 재기동 → 잡 유실 0)

## 3. 파일럿 평가 (M6)

1. 파일럿 고객의 실제 카피 1,000건+ 블라인드 검사
2. 전 결과를 사람이 재검토 → FP/FN 라벨링
3. 리포트: 카테고리별 정밀도/재현율, revise/review 등급 적정성, 놓친 유형 분석
4. 결과를 사전/모델/임계값에 반영 후 2차 라운드 — 2라운드 연속 목표치 달성 시 베타 종료

## 4. 운영 중 상시 모니터링

- 주간: 매칭 상위 용어 분포 (특정 용어 오탐 폭주 감지), 피드백 신고 처리율
- 릴리스별: 평가 리포트 `reports/eval-<version>.md` 보존 — 버전 간 품질 추세 추적
- 분기: 사어화 후보 검토(12개월 무활동 용어), 카테고리 커버리지 갭 분석
