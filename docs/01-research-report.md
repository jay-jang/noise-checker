# 01. 리서치 보고서 — 데이터 소스, 기술, 법적 환경

> 2026-06-04, 멀티 에이전트 웹 리서치(5개 차원 + 비판 검토 + 4개 갭 보강) 결과 종합.
> 모든 출처 원본(URL 포함 전체 finding)은 `data/research-raw.json` 참조.

## 0. 요약

1. **"바로 쓸 수 있는 완성품 사전은 없다"** — 한국어 혐오표현 자원은 문장 단위 분류 코퍼스가 주류이고, 용어+유래+변형을 갖춘 구조화 lexicon은 일베/남혐 양쪽 모두 공개본이 없다. **자체 구축이 핵심 가치이자 필수 경로.**
2. **라이선스가 최우선 제약** — 가장 풍부한 출처(나무위키)는 CC BY-NC-SA(비영리)+크롤링 차단. 상업 서비스의 청정 시드는 위키백과/페미위키(CC BY-SA), Apache/MIT 데이터셋, 언론 보도의 사실 추출로 한정.
3. **실사고의 최다 유형은 남혐 도그휘슬(집게손가락 등)인데 데이터는 가장 빈약** — 비대칭 확인. 남혐 lexicon 직접 구축이 최대 차별화 포인트.
4. **오탐이 최대 사업 리스크** — 대항표현/인용/동음이의어를 혐오로 오판하면 명예훼손·업무방해 책임까지 직결. SOTA 모델도 대항표현에서 정확도 97.9%→42.7% 붕괴(고려대 2022). 한국어 오탐 전용 평가셋은 부재 → 한국형 HateCheck 자체 구축.
5. **법적 환경**: 한국엔 혐오표현 법정 정의가 없음(차별금지법 19년간 미입법). 서비스는 "판정"이 아닌 **"자문/리스크 정보 제공"**으로 포지셔닝하고, 통보 범위를 고객 내부로 한정해야 함.

## 3. 매칭/분류 기술 스택 (확정 근거)

- **정규화**: unicodedata NFKC/NFD + hgtk/jamo 자모 분해. 호환 자모(U+31xx)와 조합 자모(U+11xx) 통일 필수.
- **1차 매칭**: pyahocorasick (BSD, C 확장, pickle 직렬화 → 핫리로드). 대안 flashtext2(Rust, 동적 add/remove).
- **변형 대응**: KOTOX 17규칙(음운/도상/음차/통사/화용)을 룰엔진 청사진으로. badwordDetection2의 영문 키보드 역치환(q→ㅂ) 차용. PHISH/MESH(arXiv 2505.21380) — 음운 특징을 분류기 입력에 추가하면 음차 회피에 강함.
- **퍼지**: soynlp 초/중/종성 단위 Levenshtein — AC 매칭 후 후보에만 적용 (캐스케이드).
- **형태소**: Kiwi(웹 텍스트 87%, 사용자 사전 지원).
- **문맥 분류**: KcELECTRA-base-v2022(네이버 댓글 사전학습 — 구어체 최적) 파인튜닝. 즉시 사용 가능한 출발점: beomi/beep-KcELECTRA-base-hate, TTA-DQA 멀티라벨 KcELECTRA. ⚠️ 학습 데이터 라이선스가 모델에 전이될 수 있음 — CC BY-SA 계열로만 학습.
- **LLM 폴백**: 경계 사례만. LLM 제로샷이 Perspective 대비 recall 크게 우수(0.25 vs 0.02) 실증.
- **기존 서비스의 한계 = 우리 차별화**: 네이버 클린봇/카카오 세이프봇은 비공개·내장형이며 단순 욕설은 잡지만 **완곡 표현·스테레오타입·도그휘슬에 약함**(학술 실증). Perspective API는 2026.2 종료 — 의존 금지. Hive는 한국 은어 미지원.

## 5. 법적 리스크와 설계 반영 (★ 비판 검토 발굴 — 전체 설계를 구속)

한국에는 혐오표현의 **법정 정의가 없다** (차별금지법 2007년 이후 11회+ 발의 전부 폐기, 2025 증오선동죄 발의 중). 분류 기준은 자체 기준일 수밖에 없으므로:

| 리스크 | 법적 근거 | 설계 반영 |
|---|---|---|
| 사이버 명예훼손 (정통망법 §70, 형법보다 가중) | '비방 목적'이 구성요건 — 공익 목적이면 부인됨 | 산출물을 **"리스크 확률·의견"으로 표현** (단정적 사실 적시 금지). "일베 기업" 같은 단정 라벨 금지어 관리 |
| 사실적시도 처벌 가능 (헌재 2021, 5:4 합헌) | "진실이다"만으론 면책 불가 | 공익성+비방목적 부재를 1차 방어선으로 |
| 업무방해·신용훼손 (대법 2021도6634) | 의견·가치판단은 '허위사실 유포'에서 제외 | 확률 스코어+근거 제시 형태 유지 |
| 무고 (형법 §156) | 신고자의 진실 확신 필요 | **외부 신고 기능 미제공** — 신고 판단·실행은 고객 귀속 |
| 공연성 | 제3자 공표 시 성립 | **결과는 고객사 내부 전달로 한정**. 공개 랭킹/기업 명단 기능 금지 |
| 약관 면책 한계 (약관규제법 §7) | 고의·중과실 면책 조항 무효 | 자문(advisory) 포지셔닝 + 경과실 배상 상한 + 오탐 가능성 명시 고지 + 인간 검수 권고 명문화 |
| 분류 정당성 | 인권위 정의('사회적 소수자 대상성')는 권고 수준 | 인권위 정의를 분류 로직의 보조 근거로 + **모든 항목의 출처·근거·검수 로그 보존** (= 02 문서의 evidence 강제와 일치) |

입법 모니터링: 국회 의안정보시스템, 국민참여입법센터, 대법원 판례속보 — 분기 추적 (증오선동죄·차별금지법 입법 시 분류 기준에 법적 앵커 생기는 동시에 오탐 책임 가중).

EU 진출 시: DSA(2024 시행) 체제에서 모더레이션 보조 도구 B2B 수요 존재. Trusted Flagger 생태계 연계 가능하나 책임 경계를 약관에 명시.

## 7. 시드 구축 우선순위 (M1 실행 계획)

1. **실사고 역추출** (evidence 자동 확보): 위키백과 집게손가락/일베 사건사고 문서 + 언론 보도 → incident 테이블 → 사고 문구에서 용어 추출
2. **위키백과/페미위키 용어** (CC BY-SA): 유래 서술 포함 항목
3. **MIT/Apache 사전 병합**: korcen 룰셋 + LDNOOBW + f-word + Curse-detection 빈도 어휘
4. **학술 분류체계 적용**: 박대아(2018) 호칭형/대체형 → 카테고리·강도 필드
5. **나무위키는 체크리스트로만**: 용어 존재 확인 → 위 청정 출처에서 재근거화. 근거를 못 찾으면 `draft` 유지
